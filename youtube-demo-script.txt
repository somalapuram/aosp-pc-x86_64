 AOSP-on-PC x86_64  —  YOUTUBE SCREEN-RECORDING SCRIPT
 One image. Two very different laptops. Intel + AMD, side by side, live.
================================================================================

HOW TO READ THIS FILE
  - Each SEGMENT has a HEADLINE (placeholder — edit/replace as you like),
    a rough DURATION, what to SHOW, and the exact STEPS / URLs.
  - "[HEADLINE: ...]" lines are the on-screen text/title cards. Change freely.
  - Everything is done on BOTH machines IN PARALLEL:
        LEFT  half of the frame  =  AMD  laptop  (Radeon, 2560x1600 @120Hz)
        RIGHT half of the frame  =  INTEL laptop (Meteor Lake, 1920x1200 @60Hz)
    Do the SAME step on both at the SAME time so the viewer sees one image
    behaving identically on two unrelated GPUs.

RECORDING SETUP (do this once, before Segment 0)
  - Put the two laptops physically side by side, or capture each screen and
    place them left/right in the editor. Record both continuously.
  - Full screen, hide nothing. The point is "this is real hardware."
  - Optional: a small label overlay on each half — "AMD Ryzen / Radeon" and
    "Intel Core / Arc(iris)". (Exact model names are in Segment 2.)
  - Keep both on wall power and Wi-Fi connected.

 SEGMENT 2  —  THE HARDWARE IS DIFFERENT                          (0:45–1:45)
--------------------------------------------------------------------------------
[HEADLINE: "Two different CPUs, two different GPUs"]

SHOW: the actual silicon under each machine, on screen.

  A) GPU identity (fastest, most visual) — in Firefox:
       URL:  https://webglreport.com/
     -> The big "Unmasked Renderer" line is the proof:
          AMD  half  ->  "AMD Radeon Graphics (radeonsi, phoenix, ...)"
          INTEL half ->  "Mesa Intel(R) Graphics (MTL)"
     Same OpenGL ES 3.2 / Mesa on both, different silicon.

  B) GPU driver, inside Firefox itself:
       URL / address bar:  about:support
     -> scroll to the "Graphics" section: renderer, driver, compositor.

  C) CPU + cores + RAM (pick ONE way):
     - Easiest visual: a terminal app.
         Install "Termux" from F-Droid (already on the device), then:
           cat /proc/cpuinfo | grep -m1 "model name"
           nproc
           cat /proc/meminfo | grep MemTotal
       Do it on both, side by side — different model names.
     - Or Settings > About for the RAM/soc summary.

[NOTE for you: the two model names go here once you read them off screen —
 leave a headline like "AMD Ryzen ___  vs  Intel Core Ultra ___".]

 SEGMENT 3  —  GPU BENCHMARK  (runs on the real GPU)             (1:45–4:00)
--------------------------------------------------------------------------------
[HEADLINE: "GPU test — hardware accelerated, not software"]

Run the SAME web GPU benchmark on both at once. All are browser-only,
no install, and they hammer the real driver (radeonsi / iris).

  PRIMARY (visual + score), pick one and run it on both:
    1. MotionMark 1.3.2  (browser graphics benchmark, gives a score)
         https://browserbench.org/MotionMark1.3.2/
    2. Volume Shader BM  (ray-marched 3D, WebGL2/WebGPU, FPS + score)
         https://www.volumeshader.dev/en
    3. WebGL Aquarium  (classic fish tank, raise fish count, watch FPS)
         https://webglsamples.org/aquarium/aquarium.html
         -> bump the fish to 5,000 / 10,000 and show the FPS counter.

  BACKUP / extra GPU stress tools (all browser-based):
    - Stress My GPU:            https://mprep.info/gpu/
    - GPU Benchmark (WebGPU):   https://gpubenchtest.com/
    - Tembrica GPU Benchmark:   https://tembrica.com/en/gpu-benchmark

STEPS: open the chosen URL on both, press Start/Run at the same time,
       let it finish, and hold on the two final scores side by side.

[HEADLINE: "CPU test — real-world responsiveness"]

browser CPU suites (Apple/Google/Mozilla governed), browser-only.

STEPS: open on both, click "Start Test", let it run to the final score,
